Betterlink 0.3.0 adds a local REST API, so a Stream Deck — or a shell script,
or anything else on your Mac — can drive the camera without touching the
window.

## The API

Off by default. Turn it on in **Settings → API**, which mints a bearer token
into the Keychain and gives you Copy and Regenerate buttons. It listens on
`127.0.0.1:8787` unless you tell it otherwise; with local-network access off,
the port is genuinely unreachable from any other machine.

What it can do: recall presets, move and center the head, zoom, read and set
every image control, and start and stop recording. `GET /status` returns the
whole picture in one call — camera state, position, zoom, controls, video mode,
recording.

A Stream Deck button is one `curl`:

```sh
curl -sS -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
     -d '{"direction":"left","durationMs":400}' \
     http://127.0.0.1:8787/gimbal/drive
```

Full reference, including every error code, is in
[`docs/API.md`](https://github.com/jfwoods/betterlink/blob/main/docs/API.md).

**The Dashboard wins.** While your hand is on the on-screen joystick or pad,
the API cannot take the head from you — a drive, stop or center is refused with
`409 gimbal_control_held`. A hand on the control is a deliberate act. The
reverse is not true: you can always take the head back from a script.

**A drive that is never stopped stops itself.** Every gimbal drive carries a
dead man's handle, so a client that crashes mid-move cannot leave the head
running forever. Send `durationMs` if you want a fixed nudge.

Authentication happens before routing, so an unauthenticated caller gets `401`
for every path — including ones that do not exist — and cannot map the API by
probing it. Requests carrying an `Origin` header are refused outright and no
CORS headers are ever sent: this is for local tools, not web pages.

## Also in this release

Two bugs found by running the API against the camera rather than by testing it
in isolation:

- Every numeric field rejected the values 0 and 1. Among them `{"factor": 1}`,
  and 1 is the minimum zoom — so zooming back out was impossible over the API.
- A stop sent while a recording was still starting was dropped, and the API
  said nothing was running while the recording came up behind it and ran on.
  A record/stop double-tap now does what you meant.
